Section 02

Assessment Overview

2.1What This Scan Is (and Is Not)

What this scan is

  • A consent-based, external vulnerability scan
  • Focused on publicly exposed services and configurations
  • Intended to highlight potential areas for review
  • Suitable for regular monitoring and early risk awareness
  • Non-intrusive and designed to identify security hygiene issues

What this scan is not

  • Not a penetration test
  • Not an exploitative assessment
  • Not an internal network review
  • Not confirmation of compromise or breach
  • Not an assessment of application logic flaws
  • Not an authentication bypass test
2.2Overview

This report presents the results of a non-intrusive external vulnerability scan conducted against ACME INC. The purpose is to provide early visibility of potential external security exposures based on publicly accessible systems, configurations, and software versions. The assessment supports informed security conversations and does not attempt to exploit vulnerabilities or disrupt live systems. It provides directional insight based on external observation only, not definitive risk ratings. The scan was conducted on 28 July 2026 and highlights potential areas of interest for further review.

Section 03

Scope of Assessment

3.1Systems Tested

The assessment focused on the primary domain owned by ACME INC, encompassing publicly accessible web applications, email services, and DNS configurations. Key components included the CMS platform, SMTP services, and DNS records. The scope was limited to external-facing systems, excluding internal networks and applications. The production environment was assessed to ensure real-world applicability of findings.

3.2Testing Approach

This was a non-intrusive external vulnerability scan, not a penetration test. The approach included reconnaissance, service identification, version detection, and configuration review. Techniques such as external scanning, banner grabbing, and header analysis were employed. No exploitation was attempted, and findings are based on external observation rather than active testing.

3.3Standards and Frameworks

The assessment aligned with industry standards such as OWASP, NIST, and PTES. These frameworks guided the testing methodology, ensuring best practices were followed. The findings relate to common security recommendations, though compliance-specific assessments were not within the scope.

3.4Testing Timeline

The scan was conducted over a single day, 28 July 2026. Preparation and configuration took place in the morning, with active scanning occurring in the afternoon. Results were analysed and compiled into this report for delivery shortly thereafter.

3.5Scope Limitations

The assessment was limited to external systems, excluding internal applications and networks. Time constraints prevented exhaustive testing of all subdomains and services. Potential blind spots include areas outside the defined scope, such as internal configurations and non-publicly accessible systems.

Section 04  •  Findings & Observations

4.2Detailed Findings — Medium
AX‑01
Outdated web server version disclosed
Medium
Category
Software Version
Affected Asset
www.acme‑inc.com
Status
Open

The web server returns a Server response header disclosing a specific version that is several releases behind the current stable branch. Publicly documented issues may be associated with this version. No exploitation was attempted; this observation is based on banner analysis only.

RecommendationUpdate to the latest supported release and suppress version disclosure in response headers to reduce fingerprinting.
AX‑02
Missing HTTP security headers
Medium
Category
Configuration
Affected Asset
Application endpoints
Status
Open

Responses omit several recommended security headers, including Content-Security-Policy and Strict-Transport-Security. Their absence increases exposure to client-side attacks such as content injection and protocol downgrade.

RecommendationImplement a baseline header policy (CSP, HSTS, X-Content-Type-Options, Referrer-Policy) and validate with an external header scanner.
AX‑03
Dangling DNS record (subdomain takeover risk)
Medium
Category
DNS
Affected Asset
legacy.acme‑inc.com
Status
Open

A CNAME record points to a de-provisioned third-party service. If the target resource can be re-registered, an attacker could serve content from the subdomain. No takeover was attempted.

RecommendationRemove the stale DNS record or reclaim the target resource, and establish a periodic review of DNS entries for orphaned records.

The mail service negotiates deprecated protocol versions and cipher suites (e.g., TLS 1.1). Modern clients are unaffected, but downgrade exposure remains for older clients.
